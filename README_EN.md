# Unity ROS2 Sensors

Custom robot sensor simulation components based on **Unity + ROS-TCP-Connector + ROS2**.

Currently implemented:

- 2D LiDAR
- 3D LiDAR
- RGB Camera
- RGB-D Camera
- More sensors will be added in the future...

Sensor data is published from Unity to ROS2 through the Unity Robotics ROS-TCP-Connector and can be visualized in RViz2.

---

## 1. Files

- `CameraImagePublisher.cs`: RGB camera, publishes `sensor_msgs/Image`
- `RGBDCameraPublisher.cs`: RGB-D camera, publishes RGB, Depth, and CameraInfo
- `LaserScan2DPublisher.cs`: 2D LiDAR, publishes `sensor_msgs/LaserScan`
- `LaserScan3DPublisher.cs`: 3D LiDAR, publishes `sensor_msgs/PointCloud2`

---

## 2. Environment

Tested environment:

- Ubuntu 22.04
- ROS2 Humble
- Unity 2020.3.48
- Unity Robotics ROS-TCP-Connector
- RViz2

This project was reproduced and tested based on the official Unity ROS2 + Nav2 + SLAM example project:

https://github.com/Unity-Technologies/Robotics-Nav2-SLAM-Example

## 3. RGB Camera

Script:

`CameraImagePublisher.cs`

Default topic:

`/camera/image_raw`

Message type:

`sensor_msgs/Image`

Default parameters:

- Frame ID: `camera_link`
- Publish Hz: `10`
- Width: `640`
- Height: `480`
- Encoding: `rgb8`

The Unity image is vertically flipped before publishing so that it is displayed correctly in ROS2 / RViz2.

Add in RViz2:

`Add → Image → /camera/image_raw`

![RGB Camera](Images/img.png)

## 4. RGB-D Camera

Script:

`RGBDCameraPublisher.cs`

Default topics:

- `/camera/color/image_raw`
- `/camera/depth/image_raw`
- `/camera/color/camera_info`
- `/camera/depth/camera_info`

RGB image encoding:

`rgb8`

Depth image encoding:

`32FC1`

Depth unit:

`m`

The current depth image is generated by casting a ray from the Unity Camera toward each pixel and obtaining the corresponding depth value from `hit.distance`.

Basic process:

Camera Pixel → ScreenPointToRay → Physics.Raycast → hit.distance → Depth Image

Therefore, objects detected by the depth camera must have a Collider.

For example:

- Box Collider
- Mesh Collider
- Sphere Collider

Default parameters:

- Width: `320`
- Height: `240`
- Publish Hz: `5`
- Min Depth: `0.1 m`
- Max Depth: `20 m`

Since the current depth implementation uses per-pixel CPU Raycast, the computational cost can become high at higher resolutions.

## 5. 2D LiDAR

Script:

`LaserScan2DPublisher.cs`

Default topic:

`/scan`

Message type:

`sensor_msgs/LaserScan`

Default Frame:

`base_scan`

Main configurable parameters:

- Publish Period Seconds
- Range Meters Min
- Range Meters Max
- Scan Angle Start Degrees
- Scan Angle End Degrees
- Num Measurements Per Scan
- Keep Scan Horizontal

Example:

- Scan Angle Start Degrees: `0`
- Scan Angle End Degrees: `-359`
- Num Measurements Per Scan: `180`

This represents an approximately 360° scan with 180 laser beams.

### Keep Scan Horizontal

The 2D LiDAR provides a `Keep Scan Horizontal` option.

When:

`Keep Scan Horizontal = true`

the LiDAR only follows the robot's Yaw while ignoring Roll and Pitch, keeping the laser scanning plane horizontal.

When:

`Keep Scan Horizontal = false`

the LiDAR fully follows the robot's Roll, Pitch, and Yaw.

This feature is mainly used to reduce false ground detections caused by robot pitch during acceleration, braking, or inertial motion.

### Ignoring Robot Pitch

The following figure shows the result with `Keep Scan Horizontal` enabled.

Even when the robot pitches, the 2D LiDAR scanning plane remains horizontal, reducing false detections of the ground.

![2D LiDAR - Keep Horizontal](Images/2d1.png)

### Considering Robot Pitch

The following figure shows the result with `Keep Scan Horizontal` disabled.

When the robot moves in the direction indicated by the blue arrow, inertial effects cause the vehicle to pitch, and the LiDAR tilts together with the robot body.

As a result, some of the rear laser beams point downward and hit the ground. In the blue boxed region, the rear laser beams can be seen detecting the ground, which may generate false obstacle information in ROS2.

![2D LiDAR - Follow Pitch](Images/2d2.png)

Debug rays:

- Red: laser ray hits an object
- Green: no object is detected within the maximum range

RViz2:

`Add → LaserScan → /scan`

## 6. 3D LiDAR

Script:

`LaserScan3DPublisher.cs`

Default topic:

`/points`

Message type:

`sensor_msgs/PointCloud2`

The 3D LiDAR generates a 3D point cloud through horizontal scanning and multi-channel vertical scanning.

Main parameters:

- Horizontal Angle Start Degrees
- Horizontal Angle End Degrees
- Horizontal Measurements
- Vertical Angle Min Degrees
- Vertical Angle Max Degrees
- Vertical Channels
- Range Meters Min
- Range Meters Max
- Keep Scan Horizontal

Example:

- Horizontal Angle Start Degrees: `0`
- Horizontal Angle End Degrees: `-359`
- Horizontal Measurements: `360`
- Vertical Angle Min Degrees: `-15`
- Vertical Angle Max Degrees: `15`
- Vertical Channels: `16`

This can simulate a 16-channel 3D LiDAR with approximately 360° horizontal scanning.

`Vertical Channels` can be configured as:

- 16
- 32
- 64

to simulate 3D LiDARs with different numbers of vertical channels.

The current PointCloud2 contains:

- x
- y
- z
- intensity

Coordinate system conversion:

Unity:

- X = Right
- Y = Up
- Z = Forward

ROS:

- X = Forward
- Y = Left
- Z = Up

Therefore:

- ROS X = Unity Z
- ROS Y = -Unity X
- ROS Z = Unity Y

The 3D LiDAR also supports `Keep Scan Horizontal`.

Debug rays:

- Red: laser ray hits an object
- Green: no object is detected within the maximum range

![3D LiDAR](Images/3d.png)

RViz2:

`Add → PointCloud2 → /points`

## 7. ROS2 Commands

View all topics:

`ros2 topic list`

View 2D LiDAR data:

`ros2 topic echo /scan --once`

Check the 3D LiDAR publishing rate:

`ros2 topic hz /points`

Check the RGB Camera publishing rate:

`ros2 topic hz /camera/image_raw`

Check RGB-D topics:

`ros2 topic hz /camera/color/image_raw`

`ros2 topic hz /camera/depth/image_raw`

---

## 8. Notes

- Unity and ROS2 must be connected correctly through ROS-TCP-Connector.
- The Frame ID must correspond to an existing TF frame in ROS2.
- 2D LiDAR, 3D LiDAR, and RGB-D Depth all use Physics.Raycast.
- Objects detected by Raycast must have a Collider.
- Increasing the number of LiDAR beams increases the computational load in Unity.
- The current RGB-D implementation uses CPU Raycast, which may have a high performance cost at higher resolutions.
- `Keep Scan Horizontal` can reduce false ground detections caused by robot Roll / Pitch.
- The 3D LiDAR publishes `PointCloud2`, not `LaserScan`.
